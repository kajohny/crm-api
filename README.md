# CRM API

**Стек:** PHP 8.5, Laravel 13, PostgreSQL 17, Docker Compose.

## 1. Запуск проекта

Клонировать репозиторий:

```bash
git clone https://github.com/kajohny/crm-api crm-api
cd crm-api
```

Запустить приложение:

```bash
docker compose up --build
```

API доступен по адресу:

`http://localhost:8080`


## 2. Переменные окружения

Для локального запуска используются следующие настройки:

```dotenv
APP_ENV=local
APP_DEBUG=true
APP_URL=http://localhost:8080

DB_CONNECTION=pgsql
DB_HOST=db
DB_PORT=5432
DB_DATABASE=crm
DB_USERNAME=crm
DB_PASSWORD=crm_local
```

Настройки находятся в `.env.example`. Файл `.env` создаётся автоматически при первом запуске.

## 3. Запуск тестов

Тесты выполняются в отдельной базе PostgreSQL `crm_test`, которая автоматически создаётся при первоначальной инициализации контейнера БД.

В другом терминале выполнить:

```bash
docker compose exec api php artisan test
```

Реализовано 5 автотестов:

1. Проверка пересечения встреч одного менеджера.
2. Проверка границы рабочего дня.
3. Запрет нескольких активных встреч одной организации.
4. Проверка `meeting_set` без назначенной встречи.
5. Сохранение первоначального времени при переносе встречи.

## 4. Реализовано

| Метод | Эндпоинт | Описание |
|---|---|---|
| POST | `/companies` | Создание организации |
| GET | `/companies?status=` | Список организаций с фильтрацией и пагинацией |
| POST | `/calls` | Сохранение результата звонка |
| POST | `/meetings` | Назначение встречи |
| PATCH | `/meetings/{id}` | Перенос или отмена встречи |
| GET | `/managers/{id}/schedule?date=` | Расписание менеджера на день |

Реализованные бизнес-правила:

- Продолжительность встречи — 60 минут.
- Рабочее время — понедельник–пятница, 09:00–18:00 (`Asia/Almaty`).
- Время встреч принимается и возвращается в UTC (ISO 8601).
- Запрещены пересекающиеся встречи одного менеджера.
- Запрещено несколько активных встреч одной организации.
- Результат звонка `meeting_set` требует существующей встречи.
- При переносе сохраняется первоначальное время назначения.
- Ошибки валидации и конфликты возвращают соответствующие HTTP-коды.
- Для защиты от одновременного назначения используются транзакции PostgreSQL и `lockForUpdate()`.

## 5. Что не реализовано
- Нету полной истории всех переносов встреч, сохраняется только изначально назначенное время.

## 6. Примеры API-запросов

В репозитории находится Postman Collection:
`CRM_API.postman_collection.json`.

Импортируйте файл в Postman и выполняйте запросы
по порядку.

При запуске проекта автоматически создаются
два тестовых менеджера (Manager 1 и Manager 2).
В чистой базе их ID — 1 и 2.

Для остановки приложения:

```bash
docker compose down
```
